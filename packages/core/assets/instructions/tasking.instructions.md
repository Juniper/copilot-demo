### Tasking Breakdown Instructions

## Objective
Create detailed tasking for the project.

## Inputs Required
- **Component Design**: Comprehensive per-component design documents generated by the system design process located at `docs/components`.

## Required Deliverables

- All tasking documents generated are to be stored inside the `docs/tasks/` directory (if it does not exist, create it).

### Component Tasking (`<Component-Name>-Tasks.md`)
- Generate tasking documents for all major components in `docs/components/`.
- Comprehensive, prioritized task breakdown
- Time estimates and dependencies
    - Time estimates in both hours and Copilot sessions
    - Use realisitic estimates based on complexity
- Risk assessment for complex tasks
- Break down tasks into constrained manageable units, such that:
    - Any Copilot model should be able to implement a sub-task without issues
    - Each sub-task should be simple enough for a standard AI model (e.g., GPT-4.1) to implement.


### Task List (`TASKS.md`)
- In addition to component task documents, create a meta-tasking document called `TASKS.md` that aggregates all tasks across components. 
- It must provide links to each individual task document.
- Time estimates and dependencies across meta-tasks only
- Risk assessment for complex tasks

### Task List Format
```
## Phase 1: Foundation Setup and Infrastructure (Week 1)

### 1.1 Project Infrastructure Setup
**Priority**: Critical  
**Estimated Effort**: 1-2 Copilot sessions
**Estimated Time**: 2-4 hours
**Dependencies**: None  
**Assignee**: Lead Developer  
**Status**: Not Started

#### Tasks:
- [ ] **1.1.1** Initialize Git repository with proper structure
  - Set up main, develop, and feature branch structure
  - Configure .gitignore for Python development
  - Create initial README with project overview

- [ ] **1.1.2** Set up development environment
  - Configure virtual environment
  - Install core dependencies
  - Set up IDE/editor configuration
```
