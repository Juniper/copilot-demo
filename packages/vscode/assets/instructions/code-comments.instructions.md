### Documentation & Explainability

- **Comment non-obvious code** and ensure everything is understandable to a mid-level developer.

- **Do not** over comment. Avoid stating the obvious or repeating what the code does.

- **Use `# TODO:` comments** for any incomplete code or areas needing further work.
- **Use `# FIXME:` comments** for known bugs or issues that need fixing.
- **Use `# NOTE:` comments** for important notes or clarifications about the code.
- **Use `# HACK:` comments** for temporary solutions or workarounds that need to be revisited.
- **Use `# OPTIMIZE:` comments** for areas that could be improved or optimized in the future.
- **Use `# REVIEW:` comments** for code that needs a second opinion or review from another developer.
- **Use `# DEPRECATED:` comments** for code that is outdated or should not be used anymore.
- **Use `# REFACTOR:` comments** for code that needs to be cleaned up or improved in structure.
- **Use `# TEST:` comments** for code that requires unit tests or additional test coverage.
- **Use `# SEE NOTES:` comments** for references to external documentation or resources related to the code.
- **Use `# USEFUL:` comments** for code snippets or functions that are particularly helpful or reusable.
- **Use `# LEARN:` comments** for code that is educational or demonstrates a concept worth noting.

- When writing complex logic, **add an inline `# Reason:` comment** explaining the why, not just the what.
